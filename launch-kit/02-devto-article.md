## Body

```markdown
I spent the last few weeks trying to keep straight what every AI
coding blog post is talking about. "Vibe coding", "agentic
coding", "context engineering", "MCP", "spec-driven development",
"cognitive debt", "guardrails" — the terms are spreading across
blog posts, official documentation, papers, and tool communities,
but I couldn't find one place that showed how they relate.

So I built a taxonomy rather than another list.

## What's in the wiki

**178 terms**, organized into **8 layers**:

1. **Paradigms** (L1) — vibe coding, agentic engineering,
   vibe engineering, agentic engineering
2. **Methodologies** (L2) — spec-driven development, context
   engineering, plan-verify-build
3. **Technologies** (L3) — LLMs, MCP, RAG, LoRA, attention,
   mixture of experts
4. **Tools** (L4) — Claude Code, Cursor, LangChain, Aider
5. **Quality** (L5) — guardrails, mechanical verification pipeline,
   hallucination checks
6. **Risks** (L6) — lethal trifecta, technical debt, vibe slop
7. **Prompting** (L7) — chain-of-thought, ReAct, few-shot
8. **Scenarios** (L8) — throwaway prototype, production
   maintenance, security-sensitive

For each term, I tried to include:
- A clear definition
- A code example (when applicable)
- 1-3 primary-source quotes
- Related terms
- External references (official docs, author blogs, papers)

## A few interesting observations

**"Vibe coding" was coined by Andrej Karpathy on 2025-02-02.**
That was an actual X post, not a blog retrospective.

**"Vibe engineering" was proposed by Simon Willison on 2025-10-07.**
He explicitly framed it as the opposite of vibe coding — professional
engineers using LLMs while staying accountable.

**"Agentic engineering" emerged in 2026.** Karpathy announced on
2026-02 that he wanted to retire vibe coding in favor of this term.
Martin Fowler's 2026-05-21 bliki also uses "agentic programming"
with a related but distinct meaning.

**These aren't synonyms.** They're layered — vibe coding is L1
Paradigm, agentic engineering is L1 Paradigm, agentic programming
is L1 Paradigm, but they have different "who accounts for the code"
relationships.

## What I learned building this

**The vocabulary problem is a taxonomy problem.** When you can
see "vibe coding" (L1) → "spec-driven development" (L2) →
"Claude Code" (L4) → "MCP" (L3) → "guardrails" (L5) → "lethal
trifecta" (L6) on the same page, you start to see where the
real problems are.

**Coverage matters more than count.** 178 terms with primary-source
citations and verified attributions is more useful than 1000 terms
generated by LLM.

**The English version is always behind.** I started in Chinese,
then translated layer by layer. Even now, my L1 translations are
stronger than my L7 translations. If you find errors, please open
an issue.

## Architecture (for the curious)

The site is deliberately simple:
- 100% static files (no backend, no build, no npm runtime deps)
- Per-layer async loading (initial JS < 30KB)
- Service Worker offline cache
- Full-text search with categorized ranking
- 8-layer relationship graph (Mermaid)
- 5-paradigm comparison
- Bilingual (zh-CN ↔ en) with localStorage persistence

Total project size: ~200 source files, ~12,000 lines of code,
~31 commits in the main branch.

## What I'd love feedback on

1. **Terms that are missing.** I tried to include everything I
   saw used in production, but I'm sure there are gaps.
2. **Classifications you disagree with.** Is `claude-code` L4 tool
   or L3 tech? Is "context engineering" L2 or L7?
3. **Attributions that are wrong.** I tried to use primary sources
   for every quote, but I'm sure I got some wrong.
4. **Terminology that shouldn't exist.** Some of these might be
   redundant.

Just open an issue or PR. The repo is MIT licensed.
```
